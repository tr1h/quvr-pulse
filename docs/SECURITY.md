# Security review (MVP)

| Area              | Control                                                                                                                                                                                                                                                                                                 | Where                                                             |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| No money movement | No signing code, no private keys, no `eth_sendTransaction`/`eth_sendRawTransaction`. Simulations and probes use `eth_call` only, from key-less probe addresses                                                                                                                                          | `providers/chain/*`, `services/scan/simulation.ts`, `contract.ts` |
| Input validation  | Zod `addressSchema` (0x + 40 hex, EIP-55 checksum when mixed-case) on every route and bot command. Invalid token routes return 404 from middleware                                                                                                                                                      | `shared/address.ts`, `apps/web/src/middleware.ts`, API routes     |
| SSRF              | User input never becomes a URL host. Outbound hosts are allowlisted, https only, private IPs blocked, redirects refused, response size capped                                                                                                                                                           | `providers/http.ts`                                               |
| Rate limiting     | Public endpoints: 30 req/min/IP for `/api/scan` and `/api/watchlist`, 12 cmd/min per Telegram chat (Redis-backed, in-memory fallback). Client-side budgets per provider                                                                                                                                 | `services/ratelimit.ts`, `providers/resilience.ts`                |
| Secrets           | API keys are read server-side only (`serverEnv()`), never exposed via `NEXT_PUBLIC_*`, redacted from logs by key name and URL pattern (unit-tested). `.env` is git-ignored                                                                                                                              | `shared/env.ts`, `shared/logger.ts`                               |
| CSP               | Per-request nonce, `strict-dynamic`, `default-src 'self'`, `frame-ancestors 'none'`, `object-src 'none'`, images only from self and Dexscreener CDN, plus nosniff, DENY framing, strict referrer, restrictive Permissions-Policy                                                                        | `middleware.ts`, `next.config.ts`                                 |
| XSS               | Token names, symbols and links are attacker-controlled: stripped of markup, control and bidi characters, and length-bounded. Links must be http(s) without credentials and open with `noopener noreferrer nofollow`. ESLint forbids `dangerouslySetInnerHTML`. Telegram output is HTML-escaped (tested) | `shared/sanitize.ts`, `eslint.config.mjs`                         |
| Token metadata    | Never executed or rendered as HTML. Image URLs accepted only from Dexscreener CDN hosts                                                                                                                                                                                                                 | `providers/market/dexscreener.ts`                                 |
| CSRF              | Watchlist mutations require a same-origin `Origin` header. The session cookie is httpOnly + SameSite=Lax                                                                                                                                                                                                | `api/watchlist/route.ts`                                          |
| Telegram webhook  | grammY verifies `X-Telegram-Bot-Api-Secret-Token` (`TELEGRAM_WEBHOOK_SECRET`, required in webhook mode). Only `POST /telegram/webhook` is served                                                                                                                                                        | `apps/telegram/src/index.ts`                                      |
| Seed phrases      | The bot never asks for keys and warns users who send messages that look like secrets                                                                                                                                                                                                                    | bot `message:text` handler                                        |
| Social provider   | Only the documented FomoAPI.io REST/WS with our own key. No fomo.family private API, no user cookies or bearer tokens, no scraping                                                                                                                                                                      | `providers/social/fomoapi.ts`                                     |
| Bot protection    | Cloudflare challenges (Blockscout public API) are reported as `blocked` and never bypassed                                                                                                                                                                                                              | `providers/http.ts`                                               |

Residual risks / follow-ups:

- The anonymous watchlist cookie is a bearer identifier; clearing it loses the list (by design, no accounts).
- The CSP allows `'unsafe-inline'` styles (Tailwind/Next runtime styles). Scripts are nonce-only.
- Put the webhook server behind TLS (reverse proxy) in production.
